Context

The problem worth solving.

Project decisions arrive through different conversations and documents. A useful memory system needs to connect that information to the right project without losing where it came from.

Architecture

How the pieces connect.

Synora normalizes Google Meet, WhatsApp, and manual text/document/image inputs through source-specific adapters. Normalized evidence feeds project routing, context intelligence, and project-bounded memory. Excalidraw is an output surface, not a second source of truth.

Contribution

What I built.

  • Developed a shared ingestion path with validation, deduplication, and project routing.
  • Connected project requirements, decisions, and architecture updates to a database-backed Project Atlas.
  • Kept source provenance attached as evidence becomes contextual project knowledge.

Engineering choices

The decisions behind it.

One memory path

Source adapters normalize their inputs before the shared pipeline. Source-specific details stay available without creating a separate memory store for every connector.

Evidence before visualization

Project state is persisted before visual synthesis. The read-only atlas reflects stored evidence and memory; editing the drawing does not silently create new evidence.

Explicit uncertainty

Ambiguous communication routing is isolated for review. Manual file routing has different unmatched-input behavior; this portfolio does not imply that every upload is automatically accepted.

Boundaries

What this does—and what needs care.

Connector setup, capture services, and AI providers must be configured for their corresponding paths. The README describes deterministic layout fallback. This case study explains architecture; it does not claim a public live service is running.

This case study is grounded in the public repository’s README, checked 1 November 2026. It describes the implementation; it is not an independent audit of the running project.
